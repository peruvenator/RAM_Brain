Return Stacked Visualizer

Portfolio Backend — Developer Handoff

The Return Stacked Advanced Visualizer (RS_advanced_visualizer_widget_web.html) is a single-file interactive web app that lets advisors build and compare custom portfolios. This handoff covers everything needed to wire it into WordPress with server-side portfolio storage tied to user accounts.

The widget is always behind a WordPress login — there is no public access. All portfolios and comparisons save to the database and are available across devices and sessions.

Before you start

Questions to answer about the WP setup

  • Is the WordPress REST API enabled? Test: visit yoursite.com/wp-json/wp/v2/users/me while logged in — you should get JSON back. Some security plugins (Wordfence, iThemes) restrict it.
  • What membership or login plugin is in use? MemberPress, Restrict Content Pro, WooCommerce Memberships? The portfolio plugin checks is_user_logged_in() and is agnostic to which membership plugin gates the page.
  • Does your membership plugin preserve URL query params after login redirect? The existing share-link feature uses ?rs_p= in the URL. If someone is sent a share link while logged out, they'll be redirected to login. Most plugins preserve the full URL — confirm this works so the share param survives the redirect.
  • Is there a staging environment? The plugin creates a DB table on activation — test there first.
  • PHP 7.4+ and WordPress 5.5+? Required.

All changes go in build_widget.py. Rebuild with py -3.11 build_widget.py after each set of changes.

Change 1 — Add RSV_API fetch wrapper

Find the // ── Saved Portfolios (localStorage) ── comment (~line 2175). Insert this block immediately before it:

build_widget.py — insert before line ~2175 
// ── API client ──
const RSV_API = {{
  _h() {{ return {{ 'Content-Type': 'application/json', 'X-WP-Nonce': RSV_CONFIG.nonce }}; }},
  async list() {{
    const r = await fetch(RSV_CONFIG.apiBase + '/portfolios', {{ headers: this._h() }});
    return r.ok ? r.json() : [];
  }},
  async load(id) {{
    const r = await fetch(RSV_CONFIG.apiBase + '/portfolios/' + id, {{ headers: this._h() }});
    return r.ok ? r.json() : null;
  }},
  async save(name, data) {{
    const r = await fetch(RSV_CONFIG.apiBase + '/portfolios', {{
      method: 'POST', headers: this._h(), body: JSON.stringify({{ name, data }})
    }});
    return r.ok ? r.json() : null;
  }},
  async remove(id) {{
    const r = await fetch(RSV_CONFIG.apiBase + '/portfolios/' + id, {{
      method: 'DELETE', headers: this._h()
    }});
    return r.ok;
  }}
}};

Step 3 Your task

Widget JS — Saved Comparisons

Comparisons use the same DB pattern as portfolios. A comparison stores a name and a list of portfolio name references (not the portfolio data itself). It's a lightweight record.

New DB table

Add to rsv_create_table() in the plugin, or create a separate activation hook:

backend/rsv-portfolios.php — add second table 
$sql2 = "CREATE TABLE IF NOT EXISTS {$wpdb->prefix}rsv_comparisons (
    id         BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    user_id    BIGINT UNSIGNED NOT NULL,
    name       VARCHAR(255)    NOT NULL,
    data       LONGTEXT        NOT NULL,
    created_at DATETIME        DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_user_id (user_id)
) {$charset};";
dbDelta( $sql2 );

New REST routes

Register alongside the portfolio routes in rsv_register_routes(). Mirror the same CRUD pattern: GET /rsv/v1/comparisons, POST, GET /{id}, PUT /{id}, DELETE /{id}. Handler logic is identical to the portfolio handlers — copy, rename, point to the new table.

Widget JS changes

Add RSV_API.listComparisons(), RSV_API.saveComparison(), RSV_API.removeComparison() methods to the existing RSV_API object (same pattern as portfolios).

Replace getSavedComparisons() / setSavedComparisons() with a _comparisonsCache variable, same as portfolios. Populate on init alongside the portfolio cache call.

Important: loadSavedComparison() currently looks up each portfolio by name synchronously. With the API cache, names are available but full portfolio data must be fetched async. Make loadSavedComparison async and use await RSV_API.load(entry.id) for each referenced portfolio slot, same as loadSavedPortfolio.

API endpoints

All routes require a logged-in session. Pass X-WP-Nonce: <value> with every request. Accessing another user's record returns 404.

Portfolios

EndpointBodyReturns
GET /rsv/v1/portfolios—Array of {{id, name, updated_at}}. No data blobs.
GET /rsv/v1/portfolios/{id}—Full row with data as parsed JSON.
POST /rsv/v1/portfolios{{name, data}}{{id, name}}
PUT /rsv/v1/portfolios/{id}{{name?, data?}}{{id}}
DELETE /rsv/v1/portfolios/{id}—{{deleted: true}}

Validation

Testing checklist

  • Tables created: After plugin activation, confirm both {prefix}_rsv_portfolios and {prefix}_rsv_comparisons exist in the database.
  • Routes accessible: While logged in, visit /wp-json/rsv/v1/portfolios — should return [], not an error.
  • Intake gate gone: Log in and open the widget — the name/email onboarding form should never appear. The widget should open directly.
  • Save round-trip: Save a portfolio, reload the page — it reappears in the "My Saved Portfolios" dropdown.
  • Cross-device: Save on one device, log in on another — portfolio is there.
  • Ownership isolation: Log in as a second test user — they see none of the first user's portfolios or comparisons.
  • Delete: Delete a portfolio — confirm it's removed from the DB, not just the UI.
  • Comparisons: Save a comparison, reload — it reappears and loads all referenced portfolios correctly.
  • Share link: Copy a share link, open it in a new tab — portfolio loads into slot 1 and the "Save to account?" banner appears.
  • Share link after login: Open a share link while logged out — confirm the membership plugin redirects to login and back to the same URL with the ?rs_p= param intact.
  • Import from file: Import an old .json portfolio backup — it saves to the DB and appears in the dropdown.
  • HubSpot attribution: Click "Share Portfolio" — verify the HubSpot form submission uses the logged-in user's email, not a cached/empty value.
  • Compute integrity: Load a saved portfolio and spot-check that stats match what was computed when it was saved.
